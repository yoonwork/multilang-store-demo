손님이 누르면 직원앱과 지표가 같이 움직여요

손님웹에서 언어를 고르고 주문 요청이나 직원 호출을 보내 보세요. 직원앱에 바로 뜨고, 확인을 누르면 관리자 지표가 바뀌어요. 상점앱에서 메뉴판을 읽혀 역번역 검수 후 승인하면 손님 메뉴에 올라가요.

손님웹 첫 화면, 얼마나 빨라질까요

QR을 찍고 메뉴 글자가 보이기까지예요. 아래 숫자는 예시 예상치이고, 실제 값은 착수 1주차에 지금 손님웹을 재서 보고드려요.

받는 중(엔진·코드)그리는 중
  • Flutter Web은 첫 그림 전에 렌더링 엔진(CanvasKit, Flutter 블로그 기준 약 1.5MB)과 앱 코드를 모두 받아야 해요.
  • Next.js는 서버가 메뉴 글자가 들어간 HTML을 먼저 보내서, 자바스크립트를 다 받기 전에도 메뉴가 보여요.
  • 측정은 같은 휴대폰·같은 네트워크 조건으로 전환 전후를 재고(Lighthouse·실기기), 목표치는 1주차에 같이 정해요.

방금 일어난 일

모든 기록에 매장 ID(storeId)가 붙어요. 운영지표는 이 기록을 매장별로 모아 계산해요.

데모가 흉내 낸 것과 실제 작업

번역·역번역데모는 미리 만든 문장이에요. 실제는 지금 연동된 AI·OCR·번역을 그대로 쓰고, 주의어 점검과 승인 단계를 앞뒤에 붙여요.
실시간 수신데모는 같은 페이지 상태와 BroadcastChannel이에요. 실제는 기존 백엔드 구조(Firebase라면 실시간 구독)를 1주차에 확인하고 정해요.
매장 분리모든 문서에 storeId를 붙이고, 점주·직원은 자기 매장만, 관리자는 읽기만 하도록 권한 규칙을 다시 써요.
13개 언어데모는 한·영·일·중(간체)·베트남어 5개만 진짜 예시 문장이고, 나머지 8개는 영어로 보여요(예시). 언어는 파일 하나 추가로 늘어나게 해요.
앱 알림데모는 화면 표시만 해요. 실제 직원앱은 푸시 알림·소리·진동을 Android·iOS에서 확인해요.
숫자지표 기준값과 속도 숫자는 모두 예시예요. 데모에서 누른 만큼만 진짜로 더해져요.
